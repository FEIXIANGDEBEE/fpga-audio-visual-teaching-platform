# 双板完整源码与工程：检查用文件夹

本文件夹汇集当前双板源码整理版，供逐项检查。器件为 EG4S20BG256，工程使用安路 TD 6.2.168116。A、B 必须分别使用各自目录里的文件。

## 文件怎么找

- `A_board/scene_a_top.al`：A 板 TD 工程入口；`A_board/source/` 为 A 板源码和工程依赖。A 板负责主画面、SDRAM、HDMI 和主要交互。
- `B_board/scene_b_top.al`：B 板 TD 工程入口；`B_board/source/` 为 B 板源码和工程依赖。B 板负责 TF、音频/FFT、麦克风、录音和分析画面。
- 两板的 `source/` 包含 Verilog、VHDL、头文件、厂商加密 IP、ADC 引脚约束及工程需要的 ROM/系数文件。根目录下也保留了一份初始化数据和头文件，这是工程原有的查找布局，请不要按文件名相同直接删去。
- `A_board/user_source/hdl_source/include/` 是 SDRAM IP 的相对路径依赖；A、B 工程中原有的 `initial_physical.sdc`、`final_effective.sdc` 和 `synthesis_recipe.tcl` 也一并保留。
- `Support/config/`：各板源码编入顺序及配置；`Support/constraints/`：原有 ADC/SDC 约束；`Support/scripts/`、`Support/tools/` 和 `Support/恢复原始源码.ps1`：本次项目的辅助脚本原样留存。`Support/reference_dependencies/` 补充部分脚本明确引用的历史辅助源码。
- `Simulation_reference/`：父版遗留和定向验证使用过的测试源文件，供参考；它们不是此次重新执行的测试。
- `Firmware/A_board/` 和 `Firmware/B_board/`：与两板源码对应的可烧录 `.bit` 和配套 `.bmk`。
- `TF_Card_Media/`：当前素材表对应的 10 图、4 音频；新卡不能只靠复制文件保证扇区匹配，详见目录说明。
- `源码与固件检查报告.md`、`固件及素材校验清单.txt`：源码覆盖、固件身份及素材身份核对结果。
- `文件清单.txt`：本文件夹各项文件的相对路径和大小，供检查。

## 查看和迁移时

`scene_a_top.al` 和 `scene_b_top.al` 中的工程根路径已改为本机当前检查目录，工程源码、模块名、文件名和逻辑没有为整理而改写。文件条目使用工程内相对路径。移动或解压到其他位置后，应在 TD 中核对并按新位置调整工程根路径；本次没有在另一台电脑上验证迁移。

`Support` 中的历史构建、审核及硬件操作脚本保留了原来的工作区和缓存路径，部分脚本还依赖历史报告或数据库；它们用于查看和追溯，不是已验证的独立重建入口。普通 TD 图形界面构建也不自动等同于原版经过保护、布局约束重绑定和签核的最终位流流程。

厂商加密 IP 以原文件复制保存，没有解密。TF 卡的图片、音频副本已放入 `TF_Card_Media/`；代码用到的字库、系数和初始化数据已随工程放入。当前文件夹只供检查，本次没有生成 ZIP 或 RAR。
